# Search Benchmark Command (benchmark_search)

## User Intent

User's original words: "Follow @development_rules.md closely. Your task is to create a single process single threaded search function benchmark script to evaluate the retrieval speed of the search engine and showcase the example results. Your goal is to achieve 20 search per second in the script. Each search should results in top 20 results. You need to profile the performance and bottleneck during the development."

Rephrasing: Create a single-process, single-threaded benchmark script to measure search retrieval performance, profile bottlenecks, and display example search results. Target throughput is 20 searches per second, with each search returning the top 20 results.

## Implementation Approach

The benchmark is implemented as a Django management command (`benchmark_search`) that:

1. Generates test queries by sampling random article titles from the database
2. Executes searches sequentially using the production `search_hybrid()` function
3. Measures throughput (searches per second) and latency metrics
4. Profiles execution with cProfile to identify performance bottlenecks
5. Displays example search results with scores

The command uses single-threaded execution to measure pure search performance without concurrency effects, enabling accurate bottleneck identification.

## Usage

### Basic Usage

```bash
# Run benchmark with default settings (1000 searches)
python wiki_search/manage.py benchmark_search

# Run with custom number of searches
python wiki_search/manage.py benchmark_search --num-searches 500

# Run with verbose logging
python wiki_search/manage.py benchmark_search --verbose

# Disable example result display
python wiki_search/manage.py benchmark_search --no-show-examples

# Custom profile output file
python wiki_search/manage.py benchmark_search --profile-output search_benchmark_profile.txt
```

### Command Options

- `--num-searches N`: Number of searches to execute (default: 1000)
- `--profile`: Enable cProfile profiling (default: True, always enabled)
- `--profile-output PATH`: Output file for cProfile statistics (default: `search_benchmark_profile.txt`)
- `--verbose`: Enable verbose logging
- `--show-examples`: Display example search results (default: True)
- `--no-show-examples`: Disable example result display

## Output Format

### Console Output

The command displays:
1. Progress bar during execution (using tqdm)
2. Summary metrics:
   - Total searches executed
   - Total time elapsed
   - Throughput (searches/second)
   - Average latency per search
   - Target vs actual comparison (20 searches/sec target)
3. Top bottlenecks from cProfile analysis (top 20 functions by cumulative time)
4. Example search results: First 5 queries with their top 3 results showing:
   - Query text
   - Result article titles
   - Relevance scores

### Log Files

- Execution log: `benchmark_search.log` (detailed execution log with timestamps)
- Profile statistics: `search_benchmark_profile.txt` (cProfile output with top 50 functions)

## Performance Target

Target: **20 searches per second**

The benchmark measures raw search performance in a single-threaded environment. Each search:
- Uses `search_hybrid()` with default settings (TF-IDF weight 0.7, PageRank weight 0.3)
- Returns exactly 20 results per query
- Executes sequentially without concurrency

If the target is not met, the cProfile output and bottleneck analysis identify the limiting factors (typically database query performance, tokenization overhead, or score computation).

## Implementation Details

### Query Generation

Test queries are generated by randomly sampling article titles from the database:
- Loads a random subset of article titles using Django ORM
- Ensures queries are realistic (actual Wikipedia article titles)
- Prevents cache effects by using random sampling

### Profiling

The command uses cProfile to measure:
- Function-level timing (cumulative and per-call)
- Database query patterns
- Tokenization overhead
- Score computation time

Profile statistics are sorted by cumulative time to highlight bottlenecks.

### Metrics Collection

The benchmark collects:
- **Throughput**: Total searches / total time
- **Latency**: Average time per search
- **Result validation**: Ensures each search returns exactly 20 results
- **Profile summary**: Top N functions consuming the most time
